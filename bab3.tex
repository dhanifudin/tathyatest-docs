\chapter{METODE PENELITIAN}\label{bab-iii-metode-penelitian}

\section{Metode Penelitian}\label{metode-penelitian}

Penelitian ini menggunakan metode Prototyping untuk mengembangkan TathyaTest: Test Case Generator Otomatis. Pendekatan Prototyping dipilih karena sifatnya yang iteratif, memungkinkan pengujian dan perbaikan berkelanjutan berdasarkan umpan balik pengguna. Pada tahap awal, prototipe TathyaTest akan dibuat dengan fitur dasar yang mengarah pada pengujian CRUD sederhana (Create, Read, Update, Delete) untuk menguji kemampuan dasar sistem dalam menghasilkan test case otomatis, sebelum akhirnya beralih ke aplikasi yang lebih kompleks.

Metode Prototyping memungkinkan pengembangan alat dilakukan secara bertahap, dengan setiap prototipe diuji dan disempurnakan berdasarkan temuan dari pengujian dan umpan balik pengguna. Dalam konteks TathyaTest, prototipe awal akan difokuskan pada pembuatan test case otomatis yang dapat menguji operasi dasar pada aplikasi CRUD, yang mencakup pengujian fungsionalitas seperti penambahan data, pembacaan data, pembaruan data, dan penghapusan data. Alur lengkap metode prototyping yang digunakan dalam penelitian ini ditunjukkan pada Gambar \ref{fig:prototyping-flow}.

\section{Desain Penelitian}\label{desain-penelitian}

Desain penelitian ini adalah eksperimen dengan pendekatan deskriptif-analitik. Penelitian ini bertujuan untuk mengembangkan dan menguji TathyaTest secara bertahap melalui serangkaian iterasi Prototyping. Seperti yang digambarkan pada Gambar \ref{fig:prototyping-flow}, proses pengembangan dimulai dari pembuatan prototipe awal dengan fitur CRUD sederhana, kemudian dilanjutkan dengan uji coba dan pengumpulan umpan balik pengguna. Jika diperlukan perbaikan, prototipe akan disempurnakan sebelum dilanjutkan ke tahap berikutnya. Setelah prototipe dasar stabil, pengembangan akan diperluas untuk mendukung pengujian lintas browser menggunakan Playwright dan diuji dengan dataset internal dari aplikasi-aplikasi di Jurusan Teknologi Informasi.

Tahap awal penelitian akan fokus pada pembuatan prototipe TathyaTest yang dapat menghasilkan test case otomatis untuk aplikasi berbasis web dengan operasi CRUD sederhana. CRUD adalah fungsi dasar yang sering digunakan dalam aplikasi web, yang mencakup Create (menambahkan data baru), Read (membaca atau mengambil data), Update (memperbarui data yang ada), dan Delete (menghapus data). Prototipe awal TathyaTest akan diuji dengan aplikasi CRUD sederhana (misalnya, sistem manajemen data atau aplikasi form input) yang dapat mencakup operasi-operasi ini untuk memvalidasi bahwa TathyaTest dapat menghasilkan test case otomatis yang menguji skenario-skenario dasar aplikasi berbasis web.

Setelah prototipe awal dikembangkan, uji coba dilakukan dengan aplikasi berbasis web sederhana yang hanya mencakup operasi CRUD. Pengguna seperti tim QA atau pengembang aplikasi akan memberikan umpan balik mengenai fungsionalitas, kegunaan, dan efektivitas TathyaTest dalam menghasilkan test case otomatis. Umpan balik ini akan digunakan untuk menyempurnakan alat. Berdasarkan hasil uji coba dan umpan balik pengguna, TathyaTest akan disempurnakan untuk mendukung pengujian aplikasi yang lebih kompleks dengan fitur tambahan seperti pengujian untuk form dinamis dan modul interaktif.

Setelah pengujian CRUD sederhana selesai, TathyaTest akan diperluas untuk mendukung pengujian lintas browser menggunakan Playwright. Playwright akan digunakan untuk mengeksekusi test case otomatis yang dihasilkan oleh TathyaTest, yang memungkinkan pengujian aplikasi berbasis web di berbagai platform (Chrome, Firefox, dan WebKit). Setelah memastikan bahwa prototipe dasar dapat menangani operasi CRUD dengan baik, TathyaTest akan diuji dengan aplikasi yang lebih kompleks seperti Kompen, Jayanti, dan Whistleblower. Dataset internal aplikasi ini akan digunakan untuk menguji kemampuan TathyaTest dalam menghasilkan test case otomatis yang mencakup fungsionalitas aplikasi yang lebih kompleks.

\section{Metode Pengumpulan Data}\label{metode-pengumpulan-data}

Data yang digunakan dalam penelitian ini berasal dari dua sumber utama. Pertama, dataset CRUD sederhana yang akan digunakan untuk pengujian awal, yang mencakup data aplikasi berbasis web dengan operasi CRUD dasar. Data ini akan digunakan untuk menguji kemampuan awal TathyaTest dalam menghasilkan test case otomatis untuk pengujian fungsi-fungsi dasar aplikasi berbasis web. Kedua, dataset internal aplikasi seperti Kompen, Jayanti, dan Whistleblower akan digunakan setelah prototipe awal disempurnakan. Dataset ini akan menyediakan data pengguna dan elemen-elemen aplikasi yang akan diuji untuk memvalidasi pengujian otomatis yang dilakukan oleh TathyaTest.

Dataset internal aplikasi mencakup struktur database, data pengguna dummy yang aman untuk pengujian, dan berbagai skenario penggunaan yang umum terjadi pada setiap aplikasi. Dataset ini akan digunakan untuk memastikan bahwa test case yang dihasilkan oleh TathyaTest relevan dengan konteks penggunaan sebenarnya dan dapat mendeteksi potensi error atau bug yang mungkin terjadi dalam operasional aplikasi.

Proses dimulai dengan input domain atau URL aplikasi web yang akan diuji. TathyaTest kemudian melakukan crawling aplikasi web menggunakan pustaka Colly untuk Golang, yang memungkinkan sistem untuk menjelajahi seluruh halaman aplikasi dan mengidentifikasi struktur navigasi aplikasi. Setelah crawling selesai, TathyaTest melakukan ekstraksi elemen HTML menggunakan Goquery, sebuah pustaka Go yang menyediakan API mirip jQuery untuk parsing dan manipulasi dokumen HTML. Proses ekstraksi ini mengidentifikasi elemen-elemen penting seperti form input, tombol, link, tabel, dan elemen interaktif lainnya.

Dataset internal yang telah disiapkan sebelumnya kemudian diintegrasikan ke dalam proses pemetaan elemen. Dataset ini berisi informasi seperti kredensial pengguna untuk testing, data dummy untuk operasi CRUD, dan skenario penggunaan yang umum terjadi. Dengan memanfaatkan dataset ini, TathyaTest dapat memetakan elemen-elemen HTML yang telah diekstraksi ke dalam test case yang relevan dan kontekstual. Misalnya, form login akan dipetakan dengan kredensial pengguna dari dataset, sedangkan form input data akan dipetakan dengan data dummy yang sesuai.

Proses generate test case menghasilkan kode pengujian dalam format yang dapat dieksekusi oleh Playwright. Setiap test case mencakup langkah-langkah pengujian seperti navigasi ke halaman tertentu, pengisian form, klik tombol, dan verifikasi hasil. Sebelum dieksekusi, test case akan melalui proses validasi untuk memastikan bahwa struktur kode benar dan tidak ada error sintaks. Jika validasi gagal, sistem akan kembali ke tahap pemetaan untuk memperbaiki test case yang bermasalah.

Setelah validasi berhasil, test case dieksekusi menggunakan Playwright yang mendukung pengujian lintas browser pada Chrome, Firefox, dan WebKit. Hasil pengujian dicatat dan dikategorikan sebagai Pass (berhasil) atau Fail (gagal) dengan detail error jika terjadi kegagalan. Hasil pengujian ini kemudian dapat digunakan untuk analisis lebih lanjut dan perbaikan aplikasi yang diuji.

\section{Teknik Analisis Data}\label{teknik-analisis-data}

Analisis data dalam penelitian ini dilakukan dengan pendekatan kualitatif dan kuantitatif untuk memperoleh pemahaman menyeluruh mengenai efektivitas TathyaTest. Analisis kualitatif dilakukan melalui pengumpulan umpan balik dari pengguna dan tim QA yang menggunakan TathyaTest. Umpan balik ini mencakup evaluasi terhadap kemudahan penggunaan (usability), efektivitas dalam menghasilkan test case yang relevan, dan kemampuan alat dalam mendeteksi bug atau error pada aplikasi yang diuji. Wawancara dan observasi juga dilakukan untuk memahami pengalaman pengguna dalam menggunakan TathyaTest dan mengidentifikasi area yang perlu diperbaiki.

Analisis kuantitatif dilakukan dengan mengukur beberapa metrik kinerja TathyaTest. Pertama, cakupan pengujian (test coverage) diukur dengan membandingkan jumlah elemen aplikasi yang diuji dengan total elemen yang ada pada aplikasi. Metrik ini memberikan indikasi seberapa menyeluruh pengujian yang dilakukan oleh TathyaTest. Kedua, efisiensi waktu diukur dengan membandingkan waktu yang dibutuhkan untuk menghasilkan dan menjalankan test case otomatis dengan waktu yang dibutuhkan untuk pengujian manual. Ketiga, tingkat akurasi diukur dari persentase test case yang berhasil mendeteksi bug atau error yang ada pada aplikasi dibandingkan dengan total test case yang dijalankan.

Selain itu, analisis juga dilakukan terhadap jumlah dan jenis bug yang terdeteksi oleh TathyaTest, serta perbandingan dengan hasil pengujian manual untuk validasi. Data-data kuantitatif ini akan dianalisis menggunakan statistik deskriptif dan disajikan dalam bentuk tabel dan grafik untuk memudahkan interpretasi hasil penelitian.

\section{Validitas dan Keandalan}\label{validitas-dan-keandalan}

Untuk memastikan validitas dan keandalan hasil penelitian, beberapa langkah berikut akan diambil. Pertama, pengujian ulang (retest) dilakukan dengan menjalankan test case otomatis yang sama beberapa kali untuk memastikan bahwa TathyaTest menghasilkan hasil yang konsisten dan dapat diandalkan. Konsistensi hasil ini penting untuk memvalidasi bahwa alat tidak menghasilkan false positive atau false negative secara acak.

Kedua, uji perbandingan (comparative testing) dilakukan dengan membandingkan hasil pengujian otomatis yang dihasilkan TathyaTest dengan hasil pengujian manual yang dilakukan oleh tim QA berpengalaman. Perbandingan ini mencakup jumlah bug yang terdeteksi, jenis bug, dan waktu yang dibutuhkan untuk pengujian. Hasil perbandingan ini akan menunjukkan apakah TathyaTest dapat memberikan hasil yang setara atau lebih baik dalam hal cakupan dan efisiensi pengujian.

Ketiga, validasi ahli (expert validation) dilakukan dengan meminta pakar di bidang software testing dan quality assurance untuk mengevaluasi test case yang dihasilkan oleh TathyaTest. Pakar akan menilai relevansi test case, kelengkapan skenario pengujian, dan kualitas kode test yang dihasilkan. Umpan balik dari pakar ini akan digunakan untuk meningkatkan kualitas TathyaTest.

Keempat, triangulasi data dilakukan dengan menggunakan multiple data sources dan metode pengumpulan data yang berbeda untuk memvalidasi temuan penelitian. Data dari pengujian otomatis, pengujian manual, umpan balik pengguna, dan evaluasi pakar akan dibandingkan dan dianalisis untuk memastikan validitas hasil penelitian. Dengan pendekatan multi-metode ini, penelitian dapat menghasilkan kesimpulan yang lebih robust dan dapat dipercaya.
