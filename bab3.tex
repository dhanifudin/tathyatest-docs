\chapter{METODE PENELITIAN}\label{bab-iii-metode-penelitian}

\section{Pendekatan Penelitian}\label{pendekatan-penelitian}

Penelitian ini menggunakan metode Prototyping untuk mengembangkan TathyaTest: Test Case Generator Otomatis. Pendekatan Prototyping dipilih karena sifatnya yang iteratif, memungkinkan pengujian dan perbaikan berkelanjutan berdasarkan umpan balik pengguna. Pada tahap awal, prototipe TathyaTest akan dibuat dengan fitur dasar yang mengarah pada pengujian CRUD sederhana (Create, Read, Update, Delete) untuk menguji kemampuan dasar sistem dalam menghasilkan test case otomatis, sebelum akhirnya beralih ke aplikasi yang lebih kompleks.

Metode Prototyping memungkinkan pengembangan alat dilakukan secara bertahap, dengan setiap prototipe diuji dan disempurnakan berdasarkan temuan dari pengujian dan umpan balik pengguna. Dalam konteks TathyaTest, prototipe awal akan difokuskan pada pembuatan test case otomatis yang dapat menguji operasi dasar pada aplikasi CRUD, yang mencakup pengujian fungsionalitas seperti penambahan data, pembacaan data, pembaruan data, dan penghapusan data.

\section{Desain Penelitian}\label{desain-penelitian}

Desain penelitian ini adalah eksperimen dengan pendekatan deskriptif-analitik. Penelitian ini bertujuan untuk mengembangkan dan menguji TathyaTest secara bertahap melalui serangkaian iterasi Prototyping, yang terdiri dari langkah-langkah berikut:

\subsection{Pembuatan Prototipe Awal (CRUD Sederhana)}

Tahap awal penelitian akan fokus pada pembuatan prototipe TathyaTest yang dapat menghasilkan test case otomatis untuk aplikasi berbasis web dengan operasi CRUD sederhana. CRUD adalah fungsi dasar yang sering digunakan dalam aplikasi web, yang mencakup:
\begin{itemize}
    \item Create: Menambahkan data baru
    \item Read: Membaca atau mengambil data
    \item Update: Memperbarui data yang ada
    \item Delete: Menghapus data
\end{itemize}

Prototipe awal TathyaTest akan diuji dengan aplikasi CRUD sederhana (misalnya, sistem manajemen data atau aplikasi form input) yang dapat mencakup operasi-operasi ini. Hal ini dilakukan untuk memvalidasi bahwa TathyaTest dapat menghasilkan test case otomatis yang menguji skenario-skenario dasar aplikasi berbasis web.

\subsection{Uji Coba dan Umpan Balik Pengguna}

Setelah prototipe awal dikembangkan, uji coba dilakukan dengan aplikasi berbasis web sederhana yang hanya mencakup operasi CRUD. Pengguna (misalnya tim QA atau pengembang aplikasi) akan memberikan umpan balik mengenai fungsionalitas, kegunaan, dan efektivitas TathyaTest dalam menghasilkan test case otomatis untuk operasi CRUD. Umpan balik ini akan digunakan untuk menyempurnakan alat.

\subsection{Perbaikan dan Pengembangan Fitur Lanjutan}

Berdasarkan hasil uji coba dan umpan balik pengguna, TathyaTest akan disempurnakan untuk mendukung pengujian aplikasi yang lebih kompleks. Fitur tambahan seperti pengujian untuk form dinamis dan modul interaktif akan ditambahkan pada prototipe.

\subsection{Pengembangan Fitur Pengujian Lintas Browser dengan Playwright}

Setelah pengujian CRUD sederhana selesai, TathyaTest akan diperluas untuk mendukung pengujian lintas browser menggunakan Playwright. Playwright akan digunakan untuk mengeksekusi test case otomatis yang dihasilkan oleh TathyaTest, yang memungkinkan pengujian aplikasi berbasis web di berbagai platform (Chrome, Firefox, WebKit).

\subsection{Pengujian dengan Aplikasi Dataset Internal}

Setelah memastikan bahwa prototipe dasar dapat menangani operasi CRUD dengan baik, TathyaTest akan diuji dengan aplikasi yang lebih kompleks (seperti Kompen, Jico, Jayanti, dan Whistleblower). Dataset internal aplikasi ini akan digunakan untuk menguji kemampuan TathyaTest dalam menghasilkan test case otomatis yang mencakup fungsionalitas aplikasi yang lebih kompleks.

\section{Metode Pengumpulan Data}\label{metode-pengumpulan-data}

Data yang digunakan dalam penelitian ini akan berasal dari dua sumber utama:

\subsection{Dataset CRUD Sederhana}

Dataset ini akan digunakan untuk pengujian awal, yang mencakup data aplikasi berbasis web dengan operasi CRUD dasar. Data ini akan digunakan untuk menguji kemampuan awal TathyaTest dalam menghasilkan test case otomatis untuk pengujian fungsi-fungsi dasar aplikasi berbasis web.

\subsection{Dataset Internal Aplikasi}

Setelah prototipe awal disempurnakan, dataset internal aplikasi (seperti Kompen, Jico, Jayanti, dan Whistleblower) akan digunakan. Dataset ini akan menyediakan data pengguna dan elemen-elemen aplikasi yang akan diuji untuk memvalidasi pengujian otomatis yang dilakukan oleh TathyaTest.

\section{Langkah-langkah Pengembangan TathyaTest}\label{langkah-langkah-pengembangan-tathyatest}

Pengembangan TathyaTest mengikuti pendekatan Prototyping dengan langkah-langkah sebagai berikut:

\subsection{Pembuatan CRUD Sederhana}

Prototipe awal akan dibuat dengan aplikasi berbasis web sederhana yang hanya melibatkan operasi CRUD. Prototipe ini akan diuji dengan menghasilkan test case otomatis yang mencakup setiap fungsi CRUD.

\subsection{Pemetaan Elemen HTML ke Test Case}

Setelah elemen-elemen HTML diidentifikasi dalam aplikasi CRUD, TathyaTest akan memetakan elemen-elemen tersebut ke dalam test case otomatis yang relevan. Setiap test case akan mencakup langkah-langkah pengujian untuk elemen-elemen tersebut, seperti mengisi formulir, mengklik tombol, dan memverifikasi akses.

\subsection{Pengujian dengan Playwright}

Test case yang dihasilkan oleh TathyaTest akan dieksekusi menggunakan Playwright, yang memungkinkan pengujian lintas browser pada aplikasi berbasis web yang diuji.

\subsection{Evaluasi dan Perbaikan Sistem}

Evaluasi dilakukan setelah pengujian untuk menilai keefektifan TathyaTest dalam menghasilkan test case otomatis yang akurat dan relevan dengan aplikasi berbasis web. Umpan balik dari pengujian akan digunakan untuk menyempurnakan sistem.

\section{Teknik Analisis Data}\label{teknik-analisis-data}

Analisis data dilakukan dengan pendekatan kualitatif dan kuantitatif:

\subsection{Analisis Kualitatif}

Umpan balik dari pengguna dan tim QA akan digunakan untuk mengevaluasi apakah TathyaTest dapat meningkatkan efisiensi pengujian dan apakah alat ini memenuhi kebutuhan pengguna.

\subsection{Analisis Kuantitatif}

Cakupan pengujian akan diukur dengan membandingkan jumlah test case yang dihasilkan oleh TathyaTest dengan fungsionalitas aplikasi yang diuji. Waktu yang dibutuhkan untuk menjalankan test case otomatis juga akan dianalisis untuk mengukur efisiensi TathyaTest.

\section{Validitas dan Keandalan}\label{validitas-dan-keandalan}

Untuk memastikan validitas dan keandalan hasil penelitian, beberapa langkah berikut akan diambil:

\begin{itemize}
    \item \textbf{Pengujian Ulang:} Pengujian test case otomatis akan dilakukan beberapa kali untuk memastikan bahwa TathyaTest menghasilkan hasil yang konsisten dan dapat diandalkan.
    \item \textbf{Uji Perbandingan:} Hasil pengujian otomatis akan dibandingkan dengan pengujian manual untuk memastikan bahwa TathyaTest dapat memberikan hasil yang setara atau lebih baik dalam hal cakupan dan efisiensi pengujian.
\end{itemize}
